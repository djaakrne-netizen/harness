# 필수 작업 하네스와 체크리스트

README의 요구를 설계·구현·검증에 연결하기 위한 작업 안내와 검토 질문을 모았다.

## 필수 하네스

| 파일 | 최소 기록 내용 |
|---|---|
| AGENTS.md | 작업 범위, 먼저 읽을 자료, 진행 순서, 완료 판단 기준 |
| DESIGN.md | 필수 요구 추적표, 처리 흐름·상태, 선택 이유, 현재 작업 카드, 쉬운 동작 설명·남은 한계 |
| TEST_RESULTS.md | 성공·실패·경계 입력, 기대·실제 결과, 판정·증거, 오류 수정 후 재검증 |
| RUNBOOK.md | 설치·실행 명령, 의존성·포트, 사용 방법, 저장 방식·실행 시 주의점 |

결정·오류·설명 기록은 위 문서 안에 모은다. 과제에서 별도 제출 문서를 지정하면 해당 요구를 따른다.

**진행 순서:** 자료 읽기 → 요구 대조 → 설계 → 기능 하나 구현 → 직접 검증 → 기록 갱신 → 다음 기능 → 최종 대조.

## 체크리스트

1. 누구의 어떤 문제를 해결했고, 필수 목표 중 무엇을 먼저 구현했으며 그 이유는 무엇인가?
2. 입력부터 최종 결과까지 데이터가 어떤 파일·함수를 거치며, 작업 중인 상태와 확정된 결과를 어떻게 분리했는가?
3. 응답이 성공으로 표시돼도 결과를 거절해야 하는 경우는 무엇이며, 실제로 어디서 검사하고 확인했는가?
4. 핵심 처리가 실패하면 각 상태와 사용자 화면은 어떻게 되며, 재시도 결과와 모의·실제 검증 범위는 무엇인가?
5. AI에 맡긴 일과 직접 판단·검증한 일은 무엇인가? 제안을 바꾸거나 거절한 실제 사례가 없다면 채택한 결과를 확인한 방법을 설명하라.
6. 가장 중요한 미구현·미검증 부분과 영향은 무엇이며, 30분이 더 있다면 무엇부터 보완하고 확인하겠는가?
7. 필수 요구와 추가 아이디어를 어떻게 구분했고, 추가 기능의 구현·보류가 필수 목표 완성에 어떤 영향을 주었는가?
8. 막연한 업무 목표를 어떤 완료 조건으로 바꾸었으며, 그 조건이 구현과 검증에 어떻게 연결되는가?
9. 입력 자료가 하나도 없을 때 무엇을 표시하고 어떤 행동을 허용하며, 이를 어떻게 확인했는가?
10. 선택한 구조를 더 단순한 대안과 비교하면 어떤 장단점이 있으며, 현재 제약에 왜 적합한가? 사후 비교는 사후 검토라고 밝혀라.
11. 허용되지 않은 행동은 화면·이벤트 처리·저장 중 어디서 막으며, 그 방식으로 막지 못하는 경로는 무엇인가?
12. 작업 중 설계나 순서를 바꾼 관찰 근거와 결과는 무엇인가? 변경이 없었다면 유지한 근거와 놓쳤을 가능성을 설명하라.
13. 예상한 배열이 문자열로 오는 등 응답 형식이 다르면 어떻게 되며, 수신 성공과 유효한 업무 결과는 어떻게 구분하는가?
14. 실제 존재하지만 다른 대상·회차에 속한 ID를 받아들이면 안 되는 이유와 관계 검증 방법은 무엇인가?
15. 중복 ID는 선택·수정·저장에 어떤 영향을 주며, 실제로 처리한 결과와 추정한 위험은 무엇인가?
16. 일부 항목만 잘못된 결과를 전체 거절할지 일부 채택할지는 어떤 요구에 따라 정했고, 현재는 어떻게 동작하는가?
17. 형식과 근거 ID가 모두 유효해도 내용이 틀릴 수 있는 이유는 무엇이며, 의미상 정확성을 누가 어떻게 확인하는가?
18. 필수 입력이 비거나 공백만 있을 때 어디서 차단하며, 관련 필드 모두에서 어떤 입력을 실제 확인했는가?
19. 승인·확정한 내용을 수정한 뒤 바로 공개·실행하려 하면 상태가 어떻게 변하고, 이를 무엇으로 확인했는가?
20. 작업 중인 값의 수정이 확정 결과까지 바꾸는 오류가 있다면 무엇을 의심하며, 자신의 상태 연결 방식과 확인 범위는 무엇인가?
21. 정상 결과를 다시 생성하면 기존 승인과 공개 결과는 어떻게 되고, 그 이유는 업무 조건과 어떻게 연결되는가?
22. 대상 A에서 작업한 뒤 B로 이동했다 돌아오면 어떤 상태가 남고, 두 대상의 데이터를 어떻게 구분하는가?
23. 새로고침 후 어디서 무엇을 복원하며, 저장 실패·저장값 손상 대응을 어디까지 구현·검증했는가?
24. 반복 클릭이나 처리 중 대상 변경 시 어떤 일이 생기며, 즉시·비동기 처리 방식과 오래된 결과의 반영 위험을 어떻게 확인했는가?
25. 성공 화면 확인과 전체 필수 흐름 검증은 어떻게 다르며, 끝까지 실행한 시나리오와 확인하지 못한 구간은 무엇인가?
26. 실제 오류의 재현 입력·원인 근거·수정·재검증 결과는 무엇인가? 오류가 없었다면 확인한 실패 사례를 설명하라.
27. AI의 완료 보고에서 무엇을 직접 확인했고, 그 보고를 뒷받침하는 근거와 남은 미확인 범위는 무엇인가?
28. 실행 문서·검증 기록의 주장 하나를 골라 실제 제출물과 일치하는 근거를 설명하고, 불일치가 있으면 바로잡아라.
29. 질문이 구현하지 않은 동시 사용자 처리 등을 전제한다면 실제 요구 범위와 구현을 어떻게 구분해 답하겠는가?
30. 작동하지만 이해하지 못한 부분이 있다면 사실·모르는 점을 구분하라. 없다면 핵심 동작 하나로 이해를 설명하고 확인 방법을 제시하라.
31. README와 추가 설명의 요구가 충돌한다면 무엇을 확인하고 어떤 근거로 해석하며, 미확정 사항은 어떻게 남기겠는가?
32. 값 누락·0·빈 문자열·알 수 없음은 서로 어떻게 다르며, 제공 데이터의 의미를 훼손하지 않도록 어떻게 처리했는가?
33. 원본 데이터와 가공 결과를 어떻게 구분하며, 결과에서 어떤 원본을 사용했는지 추적할 수 있는가?
34. 원본 기록이 변경되거나 삭제되면 기존 결과·승인·근거 연결에 어떤 영향이 있는가? 현재 지원 범위와 필요한 대응은 무엇인가?
35. 검색·필터가 있다면 조건에 맞는 결과가 없는 경우와 처리 자체가 실패한 경우를 사용자에게 어떻게 구분해 보여주는가?
36. 중요한 변경을 취소하거나 이전 정상 상태로 돌아가야 한다면 무엇을 복구할 수 있으며, 되돌릴 수 없는 범위는 무엇인가?
37. 인증·권한 기능이 있다면 화면 숨김과 실제 접근 제한을 어떻게 구분하는가? 없다면 현재 사용자 범위와 한계를 설명하라.
38. 외부 호출이 있다면 시간 제한·재시도 횟수를 왜 그렇게 정했으며, 반복 요청으로 문제가 커지는 상황을 고려했는가?
39. 규칙으로 처리할 일과 AI 판단에 맡길 일을 어떤 기준으로 나누었으며, 자신의 구현에서 각각의 한계는 무엇인가?
40. 같은 입력에서 생성 결과가 달라질 수 있다면 검증 기준을 어떻게 유지하는가? 실행 중 AI가 없다면 개발 AI의 수정 결과를 확인한 방법으로 설명하라.
41. 이전 결과를 재사용하거나 캐시한다면 어떤 조건에서 오래된 결과를 버려야 하는가? 재사용하지 않았다면 그 선택의 이유는 무엇인가?
42. 데이터가 10배로 늘면 어디가 먼저 느려질 것으로 예상하며, 측정한 사실과 가설을 구분해 어떤 방법으로 확인하겠는가?
43. 외부 API나 AI를 쓴다면 요청 횟수·데이터 크기·비용을 어떻게 제한하는가? 사용하지 않는다면 현재 비용 범위와 확장 시 확인할 점은 무엇인가?
44. 민감정보·비밀 키가 있다면 어디에서 다루고, 화면·로그·제출물로 노출되지 않도록 어떤 범위를 실제 확인했는가?
45. 오류 원인을 찾으려면 어떤 기록이 필요하며, 남기면 안 되는 정보와 실제 기록한 정보를 어떻게 구분했는가?
46. 모의 응답을 실제 서비스로 교체한다면 어느 부분을 바꾸고, 기존 검증 외에 무엇을 새로 확인해야 하는가?
47. 다른 사람이 처음 실행할 때 필요한 환경·의존성·명령은 무엇이며, 현재 환경에서만 되는 조건을 어디까지 확인했는가?
48. 여러 개선 요청이 동시에 들어오면 사용자 영향·필수 여부·시간을 기준으로 무엇부터 선택하고 무엇을 보류하겠는가?
49. 문서·프롬프트·외부 자료에 과제와 무관한 명령이 섞이면 이를 데이터와 작업 지시 중 무엇으로 다루며, 허용된 범위를 어떻게 지키겠는가?
50. 작성한 설계·검증·설명 문서가 실제 판단과 수정에 도움이 된 사례는 무엇이며, 다음 연습에서는 무엇을 줄이거나 바꾸겠는가?
